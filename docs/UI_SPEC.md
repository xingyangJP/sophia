### 3.2 AI応答

| 項目 | 実測 |
|---|---|
| 配置 | **左寄せ・全幅。バブルなし・背景なし** |
| アバター | 28px 角（`size-7`）、角丸16px、右マージン 8px。**列幅が狭いと消える**（コンテナクエリ `@lg` 未満で非表示） |
| モデル名 | アバターの右に 15px、黒、1行省略。本文の上に必ず出る |
| 本文 | 15px / 24.375px、`oklch(0.373 0.034 259.733)`。段落間 8px |
| タイムスタンプ | 操作ボタン行の**末尾**に並ぶ（別行にしない）。色 `oklch(0.51 0 0)`、実測 幅81px×高さ17px（「8月16日 16:37」）で、行内の他要素より小さい |

### 3.3 AI応答の操作ボタン行

本文の直下、高さ 28px。**常時表示**（ホバー不要）。

- ボタン: 28×28、アイコン16px、パディング6px、角丸8px、ホバー時に `black/5` の背景
- 隙間ゼロで9個が連続配置（x座標が 28px 刻み）
- 内訳（DOMのラベルをそのまま）: 編集 / コピー / 読み上げ / **（ラベルなし1個、アイコンは ⓘ）** /
  良い応答 / 応答が悪い / 続きの応答 / 再生成 / Fork chat

## 6. 生成中の表示 ★ 実測タイムライン

`sophia-chat`（qwen3:8b）に日本語で質問を送信し、DOMを150ms間隔でサンプリングした結果。
開発機が温まった状態での1回の計測値であり、時間そのものは条件で変わる。
**重要なのは経過時間ではなく「何が画面に出ていたか」である。**

| 経過 | 画面に出ているもの |
|--:|---|
| 0 s | 送信 |
| **0.44 s** | ユーザーのバブルが出る。AI側のブロックが生成され、**モデル名だけ**が表示される。<br>その下に **点滅するドット**（直径12px、黒、円形。`animate-pulse` の輪が重なる）。<br>主アクションボタンが「停止」（白）に変わる |
| **21.4 s** | ドットが消え、**16px のスピナー（0.75秒で1回転）+「思考中...」** の行に置き換わる。<br>文字にシマー（左から右へ流れる明暗）がかかる。**折りたたまれた状態**（`aria-expanded="false"`） |
| **70.0 s** | 思考終了。ラベルが **「49秒間の思考」** に変わり、シェブロンが付く。本文の逐次表示が始まる |

### 6.1 この観察から確定した事実

1. **送信から21秒間、利用者が得られる情報は「点滅するドット」だけだった。**
   モデル名は出るが、思考中であることすら表示されない。
2. **思考中の49秒間も、既定では思考テキストは1文字も見えない。**
   出るのは「思考中...」というラベルとスピナーのみ。
3. ただし**利用者が自分でその行を展開すれば、思考テキストは逐次流れる**。
   実測: 展開後 19秒間で文字数 912 → 1230、パネル高 260px → 317px と伸び続けた。
   つまり**データは来ているが、既定で隠されている**。

### 6.2 シマー効果の実測値

「思考中...」のラベルにかかっているアニメーション:

- `background-image`: 110度の線形グラデーション。`#B4B4B4` を基調に 43%〜57% だけ `#E8E8E8` に明るくなる帯
- `background-clip: text`（文字の形で切り抜く）
- アニメーション: 1.5秒ループ、`cubic-bezier(0.7, 0, 1, 0.4)`
- 基本の文字色: `rgb(180,180,180)`

## 7. 思考モードの表示

### 7.1 トグル行

| 項目 | 実測 |
|---|---|
| 実体 | テキストボタン（`width: fit-content`）。枠も背景もなし |
| 文字 | 15px（0.9375rem）、色 `oklch(0.69 0 0)`（≒ #9E9E9E）。ホバーで gray-700 |
| 余白 | 上下パディング 2px、下マージン 8px |
| 右端 | シェブロン（開閉で上下反転） |
| 位置 | **モデル名の直下・本文の直上** |

**ラベルは3種類ある。**

| 状況 | ラベル | 付随 |
|---|---|---|
| 生成中 | 「思考中...」 | スピナー + シマー |
| 完了 | **「N秒間の思考」**（例: 49秒間の思考） | シェブロンのみ |
| 中断された | **「思考」**（秒数なし） | シェブロンのみ |

### 7.2 展開パネル

- 開閉は高さのCSSトランジション（`overflow: hidden` で刈り取りながら伸縮）
- 中身は Markdown の **引用ブロック（blockquote）** として描画される:

| 項目 | 実測 |
|---|---|
| 左の罫 | **4px 実線**、`oklch(0.928 0.006 264.531)`（≒ #E5E7EB） |
| 左パディング | 16.67px |
| 字体 | **イタリック** |
| 文字 | 15px / 24.375px、色 `oklch(0.21 0.034 264.665)`（≒ #111827） |
| 段落間 | 8px |

> **本文より思考の方が濃い色で描画されている**（本文 #374151 に対し思考 #111827）。
> 引用ブロックの既定スタイルをそのまま使っているため。

### 7.3 観察された副次的事実

- **思考テキストは英語で出力された。** 会話は日本語（「こんにちは」「日本の四季について」）
  だったが、思考部分は一貫して英語だった。
  → DESIGN.md 2.1 の未解決事項（思考部分の出力言語が未記録）について、
  **少なくとも Open WebUI 経由の qwen3:8b では英語で出る**という観測が1件得られた。
  文字数とトークン数の不整合の説明になりうるが、`eval_count` は取っていないので断定はしない。
- **思考モードのON/OFFは会話画面に出ていない。** 右上「Controls」→ 右ドロワー →
  「高度なパラメータ」の中に、Reasoning Tags / 推論の努力 として
  Temperature・max_tokens・top_k など**15項目以上と並んで**置かれている。

## 8. コードブロック

### 8.1 構造

```
┌─ 角丸16px（上のみ） ────────────────────────────────┐
│ python              ⌄折りたたむ  実行  保存  コピー │ ← 32px、sticky
├──┬──────────────────────────────────────────────┤
│ 1│ for i in range(1, 101):                        │ ← 14px monospace
│ 2│     if i % 3 == 0 and i % 5 == 0:              │
│ 3│         print("FizzBuzz")                      │
└──┴──────────────────────────────────────────────┘
  30px（行番号の溝）
```

### 8.2 実測値

| 項目 | 実測 |
|---|---|
| 実体 | **CodeMirror 6 のエディタ。しかも編集可能**（`contenteditable="true"`, `role="textbox"`） |
| ヘッダ | 高さ 32px、白背景、角丸 `16px 16px 0 0`、パディング 6px 14px、12px/16px。**`sticky`（スクロール時に上端へ貼り付く）** |
| 言語ラベル | ヘッダ左、`flex:1` + 省略記号。例「python」 |
| ヘッダのボタン | 12px、角丸6px、パディング 2px 6px、白背景、2px 間隔で右寄せ |
| ボタン内訳と幅 | 折りたたむ 88px / 実行 36px / 保存 36px / **コピー 47px** |
| 本文 | 14px / 19.6px、`monospace`、白背景 |
| 行番号の溝 | 幅 **30px**、文字色 `rgb(108,108,108)` |
| 行のパディング | 上下0、左6px 右2px |
| カーソル行 | `rgba(204,238,255,0.267)` の淡い青でハイライトされる |

### 8.3 シンタックスハイライトの色（CodeMirror 既定のライトテーマ）

| 種別 | 色 | 例 |
|---|---|---|
| キーワード | `rgb(119,0,136)` 紫 | `for`, `if`, `else` |
| 数値 | `rgb(17,102,68)` 緑 | `1`, `101` |
| 文字列 | `rgb(170,17,17)` 赤 | `"FizzBuzz"` |

**コピーはヘッダ内の「コピー」という文字ボタン**である。ホバーで現れるアイコンではない。

## 10. Sophia が真似るもの／真似ないもの

### 10.1 借りる — レイアウトと対話の骨格

| # | 借りるもの | 理由 |
|---|---|---|
| 1 | **三領域構成**（サイドバー / メッセージ列 / 下端固定の入力欄） | 会話UIとして枯れている。利用者が迷わない |
| 2 | **サイドバーは固定幅245px、折りたたみ時42pxのアイコンレール** | 16GB機の狭い画面で本文幅を確保できる。境界線ではなく明度差で分ける手法も借りる |
| 3 | **メッセージと入力欄が同じ最大幅（900px前後）を共有する** | 視線の折り返し幅が1つに揃う。日本語15pxなら1行45〜50字で読みやすい |
| 4 | **ユーザー＝右寄せバブル（最大90%）／AI＝全幅・バブルなし** | 発言者の区別に色もラベルも要らない。装飾を足さずに済む |
| 5 | **本文の字サイズは両者とも 15px / 行高1.625** | 器だけで区別する。日本語の可読性も実測で良好 |
| 6 | **入力欄をスクロール領域の外に置き、内容に応じて伸ばして上限で内部スクロール** | 生成中にスクロールしても入力欄が動かない（NFR-02の体感に効く） |
| 7 | **主アクションを1スロットに集約し、状態で意味を変える（送信⇄停止）** | FR-02。**塗りを反転させる**（黒⇄白）ので、位置を動かさずに状態が伝わる |
| 8 | **思考を「本文の上の1行トグル」として置く** | FR-17。本文の流れを乱さずに畳める |
| 9 | **完了後のラベルに所要時間を出す（「49秒間の思考」）** | ローカル推論では**これが最も有用な1情報**。「遅い＝故障」の誤解を防ぐ（DESIGN.md 2.0） |
| 10 | **思考テキストは字下げ＋イタリック＋左罫の引用ブロックで描く** | 本文と絶対に読み違えない。ただし色は本文より**薄く**する（10.2-#11） |
| 11 | **AI応答の操作行は常時表示、ユーザー発言の操作はホバー時のみ** | 主役（AIの回答）に対する操作は探させない |
| 12 | **「最下部へスクロール」を34pxの丸ピルで入力欄の上に浮かせる** | 生成中に上へスクロールしても復帰できる |
| 13 | **コードブロックのヘッダに言語（左）と操作（右）を並べ、コピーは文字ボタン** | FR-06。アイコンより発見しやすい。行番号の溝30pxも借りる |
| 14 | **モデルセレクタは入力欄の中、上方向に開き、右端を揃える** | 視線移動が最小。**各行にパラメータ数（8.2B）を出す**のは FR-08 の推奨提示に直結する |
| 15 | 角丸を**入力欄とユーザーバブルで同じ24px**にする | 「利用者が書くもの」が同じ形をしていて一体に見える |

### 10.2 借りない

| # | 借りないもの | 理由 |
|---|---|---|
| 1 | ★ **送信後21秒間「点滅するドット」だけを見せる** | **DESIGN.md 第6章が禁じている無言の待機そのもの。** Sophia は生成開始と同時に思考領域を表示し、テキストを流す（FR-17 / NFR-03） |
| 2 | ★ **思考テキストを既定で折りたたむ** | Open WebUI はデータが来ているのに隠している。Sophia は**逆**にする: 思考中は展開、本文が始まったら自動的に畳む（DESIGN.md 6章） |
| 3 | ★ **思考ON/OFFを15項目のパラメータ引き出しに埋める** | FR-18 は**会話ごとの切替**を要求している。入力欄ツールバーかヘッダに1タップで置く |
| 4 | ★ **コードブロックを編集可能な CodeMirror にする**（＋「実行」「保存」） | FR-06 が要るのは**ハイライトとコピーだけ**。コードブロック1個ごとにエディタを常駐させるのは16GB機で割に合わない。読み取り専用の描画にする |
| 5 | ★ **ツール／連携をプロンプトに常駐させる仕組み** | TUNING/DESIGN 2.2 で実測した**約4,550トークンの自動注入**の正体。Sophia はこの構造を持ち込まない |
| 6 | ★ **入力トークン数がどこにも出ていない** | DESIGN.md 2.2 の帰結として Sophia は**必ず出す**（TTFT / tok/s と合わせて3点） |
| 7 | AI応答ごとに操作ボタンを9個並べる（👍👎 / Fork / 読み上げ …） | Sophia に必要なのはコピー・再生成・編集まで。ボタンは3〜4個に絞る |
| 8 | 全メッセージにタイムスタンプ行を持たせる | 1件につき28pxの行が増える。ローカルの個人利用では価値が薄い。必要ならホバー時に出す |
| 9 | 空状態の見出しに**モデルIDをそのまま出す**（`sophia-chat:latest`） | Sophia は自分の名前を出す。モデルIDは設定画面の情報 |
| 10 | 英語のままの提案カード | 日本語UIに英語の定型文が並ぶのは不整合。そもそもA1では提案カード自体がスコープ外 |
| 11 | 思考テキストを本文より**濃い**色で描く | 主従が逆転する。Sophia は思考を本文より**薄く**（例: 本文チャコール `#434548` に対し思考は一段落とす） |
| 12 | Controls ドロワーが本文幅を341px奪う | 設定はモーダルかオーバーレイにし、会話の行幅を変えない。行幅が変わると読み位置を見失う |
| 13 | 中断時に思考ラベルから秒数が消える（「思考」だけになる） | 中断でも**経過秒数は残す**（例:「32秒間の思考（中断）」）。何秒待ったかは利用者の判断材料 |

### 10.3 Sophia 固有の判断（Open WebUI に無いもの）

| 項目 | 方針 |
|---|---|
| 配色 | Open WebUI の対話画面は**アクセント色を一切使っていない**（白と灰のみ）。Sophia は逆にテラコッタ `#D08256` を**面積ゼロで**効かせられる余地が大きい。使いどころは「思考中のスピナー」「逐次表示のキャレット」「トークン予算の警告」に限定する |
| 地の色 | Open WebUI は純白 `#FFFFFF`。Sophia はクリーム `#FEF5EB` を地にする。ユーザーバブルはそこからさらに一段沈めた色を作る（Open WebUI が白地に #FAFAFA を置いているのと同じ関係） |
| ネイティブ機能 | Open WebUI はブラウザアプリなので使っていないが、Sophia は Electron の vibrancy / hiddenInset を使う。**ヘッダ43pxが透明でsticky**という構成は、そのままトラフィックライトを置く帯として使える |
| バージョン表示 | Open WebUI は起動時のフッタにのみ出る。Sophia は完成条件8により**常時見える場所**に `ver 0.1.0` を置く（サイドバー最下部が候補） |
