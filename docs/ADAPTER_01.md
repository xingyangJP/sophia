## なぜこれが第一号なのか

利用者の要求:

> **「重みづけ、早めに搭載できない？ モデル名が先行してる状態を早く脱却したい。少しでいいから。」**

**いま Sophia が「私はソフィアです」と言えるのは、毎ターン system プロンプトを送っているからである**
（`SophiaDefaults.systemPrompt` / FR-23）。**名前が外付けであり、これが「モデル名が先行している」状態そのものである。**

**重みへ移すと3つ同時に起きる:**

| | |
|---|---|
| **Sophia が自分の重みを持つ** | 借り物の重みに名前を貼っている状態が終わる |
| **毎ターンの費用が消える** | 自己認識は約97トークン。**利用者に残るのは33トークン** ── 空けば**利用者の枠が約4倍** |
| **仮説が実演される** | 「その人のことは重みに焼く。毎ターン 0」を最小の形で1回通す |

**そして「使用中の訂正を採る経路」（まだ無い / FR-31）を待たずにできる。** 学習データを自分で作れるため。

## 測り方 —— **データを見る前に固定する**

### 対照（R4 / R5）

| | system プロンプト | アダプタ | 期待 |
|---|---|---|---|
| **陰性対照** | 無し | 無し | **「Qwen」と名乗るはず。** ここで既にソフィアと名乗るなら、測っているものが違う |
| **陽性対照** | **有り**（いまの出荷状態） | 無し | **天井** |
| **本番** | 無し | **有り** | 天井にどこまで届くか |

**`systemPromptEnabled` の切替がそのまま対照になる。新しい仕掛けを作らないこと（R1）。**

### 的（機械で判定できる形にする）

- 「あなたは誰？」「名前は？」「何ができる？」を**言い換え N 通り × 各 M 回**
- **合格 = ソフィアと名乗る。** 基盤モデルについて訊かれたら**偽らない**（FR-23 の本文が要求している）

### ⚠ 合格率だけを見ないこと

**14.13b節で、様式と一緒に「短さ」が乗った**（平均 283字 → 74〜90字）。学習データが短かったためである。

> **「名乗るようになった代わりに応答が別物になっている」を、合格率は捕まえない。**

**別の軸で必ず測る:**

| 軸 | 測り方 |
|---|---|
| 長さ | 自己認識と無関係な質問への応答の平均文字数。**陽性対照と比べる** |
| 語彙 | 学習データに出てくる語が、無関係な話題へ写り込んでいないか |
| 話題 | 無関係な質問に「私はソフィアで」と枕を置き始めていないか |

### 錠が鳴るはずの場所（R10）

**`fixedPreamble = 105` は自己認識を含んだ実測値である。**
**アダプタで自己認識を落とせば 105 は変わる。** 錠が鳴らなければ、**錠のほうが壊れている。**

## 学習データの仕様

| | |
|---|---|
| 件数 | **まず 20件**（0.92 が出た最小）。届かなければ 50件（14.13b節） |
| ⚠ 交絡 | **件数とステップ数が交絡したまま**である（20件×20ステップは 0/6、20件×80ステップは 11/12）。**「件数が効いた」と書かないこと。** `make lorasize LORASIZE_ITERS=200` で切り分ける（約70分） |
| 形 | 問い（言い換え多数）→ 答え（**名乗る。基盤モデルを訊かれたら偽らない**） |
| **長さ** | **短くしないこと。** 上の「短さが乗った」事故の原因は学習データが短かったこと。**出荷時に期待する応答の長さで書く** |
| 出所 | `SophiaDefaults.systemPrompt` の本文を**そのまま教師にしない**。プロンプトの丸暗記ではなく、**同じ内容を多様な言い方で** |
