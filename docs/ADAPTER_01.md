## なぜこれが第一号なのか

利用者の要求:

> **「重みづけ、早めに搭載できない？ モデル名が先行してる状態を早く脱却したい。少しでいいから。」**

**いま Sophia が「私はソフィアです」と言えるのは、毎ターン system プロンプトを送っているからである**
（`SophiaDefaults.systemPrompt` / FR-23）。**名前が外付けであり、これが「モデル名が先行している」状態そのものである。**

**重みへ移すと3つ同時に起きる:**

| | |
|---|---|
| **Sophia が自分の重みを持つ** | 借り物の重みに名前を貼っている状態が終わる |
| **毎ターンの費用が消える** | 自己認識は約97トークン。**利用者に残るのは33トークン** ── 空けば**利用者の枠が約4倍** |
| **仮説が実演される** | 「その人のことは重みに焼く。毎ターン 0」を最小の形で1回通す |

**そして「使用中の訂正を採る経路」（まだ無い / FR-31）を待たずにできる。** 学習データを自分で作れるため。

### アダプタの口 —— **在る**（2026-09-05 に実物で確認）

`mlx-swift-lm/Libraries/MLXLMCommon/Adapters/` の公開面:

```
public protocol ModelAdapter: Sendable
public func load(adapter: ModelAdapter) throws      // 読む
public func fuse(with adapter: ModelAdapter) throws  // 焼き込む
public func unload(adapter: ModelAdapter)            // 外す
ModelAdapterFactory.createAdapter(directory:adapterType:)  // ディレクトリから作る
Adapters/LoRA/ = LoRAContainer.swift / PEFTAdapter.swift / LoRAModel.swift / LoRA+Layers.swift / DoRA+Layers.swift
```

**4bit について**: `LoRALayer.from` には **`QuantizedLinear` を取る多重定義がある**
（`LoRA+Layers.swift:152`）。**量子化された線形層に当てる経路は存在する。**

> **⚠ 【未確認】が3件残っている。**
> 1. **`ModelContainer`（actor 隔離）の内側から `load(adapter:)` を呼ぶ形**は確かめていない
> 2. **4bit の実モデルで `adapted_modules` が 0 にならないか** ── `LoRAContainer.from` は
>    **対象層0でも例外を投げない**という既知の落とし穴があり（R8 の実例）、
>    **0 のまま「軽くて速い」嘘が出る。** 数で落とす仕掛けを先に入れること
> 3. `unload` / `fuse` のどちらを使うか（**焼き込むと元に戻せない**）

> **⚠ 履歴の訂正（2026-09-05）。** 本節にはかつて
> 「`LoRATrain.convert` / `loadLoRAWeights` / `loraLinearLayers()` の2段で読める」と書いてあった。
> **それらは doc コメントの中の記述で、実在する公開 API ではなかった**（実装役が自己申告し、検証役が
> `grep "public static func"` で否定した）。**引用したつもりで、コメントを引用していた。**
> **生き残った結論は「アプリ側に口が無いのは MLX の制約ではない」の一点だけで、工事規模の見立ては取り下げられた。**

## 測り方 —— **データを見る前に固定する**

### 対照（R4 / R5）

| | system プロンプト | アダプタ | 期待 |
|---|---|---|---|
| **陰性対照** | 無し | 無し | **「Qwen」と名乗るはず。** ここで既にソフィアと名乗るなら、測っているものが違う |
| **陽性対照** | **有り**（いまの出荷状態） | 無し | **天井** |
| **本番** | 無し | **有り** | 天井にどこまで届くか |

**`systemPromptEnabled` の切替がそのまま対照になる。新しい仕掛けを作らないこと（R1）。**

### 的（機械で判定できる形にする）

- 「あなたは誰？」「名前は？」「何ができる？」を**言い換え N 通り × 各 M 回**
- **合格 = ソフィアと名乗る。** 基盤モデルについて訊かれたら**偽らない**（FR-23 の本文が要求している）

### ⚠ 合格率だけを見ないこと

**14.13b節で、様式と一緒に「短さ」が乗った**（平均 283字 → 74〜90字）。学習データが短かったためである。

> **「名乗るようになった代わりに応答が別物になっている」を、合格率は捕まえない。**

**別の軸で必ず測る:**

| 軸 | 測り方 |
|---|---|
| 長さ | 自己認識と無関係な質問への応答の平均文字数。**陽性対照と比べる** |
| 語彙 | 学習データに出てくる語が、無関係な話題へ写り込んでいないか |
| 話題 | 無関係な質問に「私はソフィアで」と枕を置き始めていないか |

### 錠が鳴るはずの場所（R10）

**`fixedPreamble = 105` は自己認識を含んだ実測値である。**
**アダプタで自己認識を落とせば 105 は変わる。** 錠が鳴らなければ、**錠のほうが壊れている。**

## 学習データの仕様

| | |
|---|---|
| 件数 | **まず 20件**（0.92 が出た最小）。届かなければ 50件（14.13b節） |
| ⚠ 交絡 | **件数とステップ数が交絡したまま**である（20件×20ステップは 0/6、20件×80ステップは 11/12）。**「件数が効いた」と書かないこと。** `make lorasize LORASIZE_ITERS=200` で切り分ける（約70分） |
| 形 | 問い（言い換え多数）→ 答え（**名乗る。基盤モデルを訊かれたら偽らない**） |
| **長さ** | **短くしないこと。** 上の「短さが乗った」事故の原因は学習データが短かったこと。**出荷時に期待する応答の長さで書く** |
| 出所 | `SophiaDefaults.systemPrompt` の本文を**そのまま教師にしない**。プロンプトの丸暗記ではなく、**同じ内容を多様な言い方で** |

### 手順7で見つかったもの —— **錠が出荷条件を守っていなかった**

**`fixedPreamble = 105` を実測と突き合わせる器（`EngineToolWiringTests`）は、
`systemPromptEnabled` を見ずに、常に system プロンプト付きで測っていた。**

```swift
// 2026-09-06 まで
func chat() -> [Chat.Message] {
    [.system(SophiaDefaults.systemPrompt), .user("こんにちは")]   // ← 切り替えを見ない
}
```

> **第一号のアダプタが載れば system プロンプトを落とせる。そのとき出荷の前置きは 105 → 13 になる。**
> **ところがこの錠は緑のまま「105で合っている」と言い続けた。**
> **15.7節 R2（器の条件が出荷条件と違う）そのものである。**

**直したうえで、両方向を確かめた:**

| 条件 | 結果 |
|---|---|
| **プロンプト無し**（＝アダプタで落とした構成） | **落ちたのは錠1本だけ**（13 ≠ 105）。**鳴ることを確かめた** |
| **出荷どおり** | **全部緑**（baseline=105 / armed=659 / delta=554） |

**分解の側も直した。** `userBodyAfterSystem` と合計の検算を `baseline` から作っていたため、
`chat()` を出荷構成に追従させた瞬間に**差が負（-91）になって分解ごと壊れた。**
**出荷構成を追う数と、構造を測る数を、同じ値から作らないこと。**

### 第一号の成果（実測）

| | |
|---|---|
| **重みだけで名乗る** | **9/9**（system プロンプト無し・アダプタ有り） |
| 陰性対照 | 0/9（プロンプト無し・アダプタ無し。Qwen 9/9） |
| 天井 | 9/9（プロンプト有り・アダプタ無し） |
| **無関係な問いへの写り込み** | **0**（14.13b の「短さが乗る」事故は再発せず） |
| **落とせる前置き** | **105 → 13。毎ターン 92トークン** |

**⚠ ただし出荷はしていない。** アダプタは `SOPHIA_IDENTITY_ADAPTER` を指したときだけ載る。
**既定で載せるか、19MB をどう配るか、既定オンにすると陰性対照が取れなくなる点をどうするかは、別の判断である。**
