## 1. 背景と目的

### 1.1 背景

生成AIを業務で使う際、入力内容が外部サービスへ送信されることが制約になる場面がある。
社内文書・顧客情報・未公開のソースコードなどは、外部APIに投げる判断がしにくい。

一方、Apple Silicon の性能向上により、7〜8B規模のモデルであれば
ローカルマシン単体で実用的な速度で動作するようになっている。

### 1.2 目的

> **独自モデルを内蔵した、ローカル完結のデスクトップAI。会話は端末の外に出ない。**

これが到達目標であり、以下の要件はすべてこの一文を分解したものである。
本プロジェクトは**2つの目的**を持ち、両者は独立して進行する。

**目的A: 外部にデータを出さずに動作する、自作のデスクトップAIアプリを作る。**
Claudeデスクトップアプリのような使用感を、ローカルモデルで実現する。
最終的には**開発者本人以外も利用できる単体アプリ**として配布する。

**目的B: 独自のモデルを作る。**
既存モデルを利用するだけでなく、**新しい重みを持つモデルそのものを開発する**。
外付けの検索機構（RAG）で振る舞いを変えるのではなく、モデル自体を作る点が要件である。
ローカルで着手し、**性能を段階的に上げ、上限に達した時点でクラウドへ移行する**。

両者の接点は「モデルファイル1個」のみ。アプリはそれを読むだけの構造とし、
どちらかの完成をもう一方が待たない設計とする（[DESIGN.md](DESIGN.md) 第4章）。

### 1.3 達成したい状態

- 機密性のある文章の作成・推敲を、外部送信なしに行える
- コードの相談を、社外に出せないソースコードに対しても行える
- 利用者が Ollama や Python などを個別に導入することなく、アプリを入れるだけで使える
- **自分のデータで鍛えた、自分だけのモデルがアプリの中で動いている**

## 2. スコープ

### 2.1 対象

**目的A（アプリ）**

- macOS（Apple Silicon）向けデスクトップアプリケーション
- ローカルでのテキスト生成（チャット・文章作成・コーディング支援）
- モデルの取得・管理・切替
- 会話履歴の保存と再開

**目的B（モデル）**

- モデルマージによる新しい重みの生成（ローカル・0円）
- LoRA/QLoRA による微調整とベースへの融合（ローカル・0円）
- 訓練データの設計と整備
- 品質評価基盤の構築
- **上限到達後のクラウドでの学習**（大規模SFT・継続事前学習）

段階と移行条件は [ROADMAP.md](ROADMAP.md) を正とする。

### 2.2 対象外（現時点）

| 項目 | 理由 |
|---|---|
| 画像生成・音声処理 | 用途に含まれない。メモリ制約上も同時実現は困難 |
| RAG（外部文書の検索付与） | **目的Bと手段が異なる**。モデル自体を作ることが要件であり、検索の外付けでは代替にならない。アプリの補助機能としては将来検討（FR-15） |
| スクラッチ事前学習 | 8B級で数千万円規模。組織的投資が必要。ROADMAP の M6 として将来の検討対象に留める |
| チーム利用・サーバ運用 | 単一マシン上の個人利用が前提 |
| Windows / Linux 対応 | 第9章の未決事項。初版は macOS のみ |
| クラウドAPI（Claude/OpenAI等）への**推論**接続 | 「外部に出さない」目的と相反する。**クラウドは学習にのみ使用し、推論はローカルを維持する** |

## 3. 用語

| 用語 | 意味 |
|---|---|
| モデル | テキスト生成を行う学習済みの重みファイル |
| GGUF | ローカル推論で標準的に使われるモデルファイル形式 |
| 量子化 | 重みを低精度化してサイズと必要メモリを減らす手法（Q4_K_M 等） |
| 推論エンジン | モデルを読み込み、トークンを生成する実行基盤 |
| コンテキスト長 | モデルが一度に扱えるトークン数。会話が長くなると古い部分が切り捨てられる |
| TTFT | Time To First Token。入力してから最初の文字が出るまでの時間 |
| 公証 | Apple による配布アプリの検証。未実施だと利用者側で警告が出る |

## 4. 前提条件と制約

### 4.1 開発環境の制約

| 項目 | 値 | 影響 |
|---|---|---|
| 開発機 | MacBook Air M3 / 16GB / **ファンレス** | 実質9〜10GBがモデル用の上限。7〜8Bが常用、14Bが限界 |
| 熱設計 | ファンなし | 長時間の連続生成で性能が2〜3割低下する |
| メモリ形態 | ユニファイドメモリ | Electron・Docker等の常駐がそのままモデル用メモリを削る |

このため、**開発機で快適に動く構成が、そのまま最低動作環境の指標になる**。

### 4.2 配布上の制約

- 配布には Apple Developer Program（年額 $99）が必要。未加入では
  利用者側で「開発元を確認できません」の警告が出て実用に耐えない
- ネイティブモジュール（`.node`）を含むため、署名と entitlements の設定が必要

### 4.3 環境上の制約

- ポート割り当ては開発機の環境台帳を正とする。開発用の Ollama は 11434、
  参照UI（Open WebUI）は 8081。8080 は他プロジェクトが使用中

## 5. 機能要件

優先度: **A** = 初版必須 / **B** = 初版後に追加 / **C** = 将来検討

| ID | 要件 | 優先 |
|---|---|:--:|
| FR-01 | 利用者の入力に対し、モデルの応答を**1トークンずつ逐次表示**する | A |
| FR-02 | 生成中の応答を利用者が**中断**できる | A |
| FR-03 | 会話を保存し、一覧から選んで**再開**できる | A |
| FR-04 | 会話を削除できる。削除は取り消せない旨を提示する | A |
| FR-05 | 用途別の**役割（システムプロンプト）を切り替え**られる（文章作成 / コーディング等） | A |
| FR-06 | 応答内のコードブロックを**シンタックスハイライト表示**し、コピーできる | A |
| FR-07 | 初回起動時に**モデルを取得**する。進捗・残量・中断・再開に対応する | A |
| FR-08 | 搭載メモリ量から**推奨モデルを提示**する（16GB→7〜8B、32GB以上→14B以上） | A |
| FR-09 | 導入済みモデルの**一覧・切替・削除**ができる | A |
| FR-10 | 生成パラメータ（temperature、コンテキスト長 等）を設定画面から変更できる | A |
| FR-11 | モデルの読込・生成に失敗した場合、原因と対処を**日本語で提示**する | A |
| FR-12 | 会話を Markdown 形式で書き出せる | B |
| FR-13 | 会話履歴を全文検索できる | B |
| FR-14 | 応答速度（TTFT / tok/s）を利用者が確認できる | B |
| FR-15 | ローカルの文書ファイルを読み込ませて質問できる（RAG） | C |
| FR-16 | アプリの自動更新 | C |
| FR-17 | 思考モード対応モデルでは、**思考テキストを本文と分けて表示**する（折りたたみ可能） | A |
| FR-18 | 思考モードを会話ごとにON/OFFできる。有効時は生成トークン上限を自動的に引き上げる | A |
| FR-19 | **ローカルのファイル・ディレクトリを参照できる**（読み取り系ツール） | B |
| FR-20 | **ローカル環境を操作できる**（ファイル書き込み・コマンド実行）。**変更系の実行前に利用者の承認を必須とする** | B |
| FR-21 | ツール定義は**必要時のみ注入**する。常時注入をしない（クライアント起因のプロンプト肥大を設計で禁止） | B |
| FR-22 | すべてのツール実行を監査ログとして記録し、後から参照できる | B |

> FR-19〜22 は 2026-08-16 追加。「チャットだけでなく、ローカル環境を参照・操作できる
> エージェントにする」という要望による。フェーズA2 の中心スコープ。
> FR-21 が要件になっているのは、ツール定義32個の常時注入（4,550トークン）が
> 応答を34秒にしていた実測（TUNING.md 第2章）を反面教師とするため。
> FR-20 の承認必須は、ファイル内容経由のプロンプトインジェクションが
> あっても変更系が人間の承認を通らずに実行されない、という安全設計を兼ねる。

## 6. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| NFR-01 | プライバシー | **入力内容および会話履歴を外部へ送信しない**。通信はモデル取得と更新確認に限定し、それ以外の外部通信を行わない |
| NFR-02 | 応答性 | 推論中も**UIが操作可能である**こと（スクロール・中断が効く）。推論をUIスレッドで実行しない |
| NFR-03 | 性能（初動） | 開発機（M3/16GB）で 7〜8B モデル使用時、**利用者に何かが表示されるまで1秒以内**。思考モード有効時は思考テキストの表示開始をもって満たすものとする |
| NFR-03b | 性能（生成速度） | 冷間で 13 tok/s 以上、**連続使用時（熱制限下）で 7 tok/s 以上**。実測の基準値は `BENCH_RESULTS.md` |
| NFR-04 | メモリ | アプリ自体の常駐メモリは 500MB 以内。モデル分を含めて 16GB 機で動作すること |
| NFR-05 | 配布性 | 利用者が**アプリ以外を導入せずに使える**こと。Ollama・Python・Homebrew等への依存を残さない |
| NFR-06 | 配布サイズ | アプリ本体は 300MB 以内。モデルは本体に同梱せず初回取得とする |
| NFR-07 | 対応環境 | macOS 14 以降 / Apple Silicon。初版は arm64 のみ |
| NFR-08 | 完全性 | 取得したモデルは sha256 で検証する。破損時は再取得を促す |
| NFR-09 | 保守性 | 推論エンジンを差し替え可能な形で抽象化する（開発時と配布時で実装が異なるため） |
| NFR-10 | 復旧性 | モデル取得の中断・容量不足・ネットワーク断から復帰できる |

## 7. 受入条件

初版（フェーズ3完了時点）を完成と判断する条件。

1. Ollama をインストールしていないMacに `.dmg` を導入し、警告なく起動できる
2. 初回起動でモデルを取得し、そのまま会話できる
3. 会話中に機内モード（ネットワーク遮断）にしても、生成が継続する
4. 5,000字程度の文章を貼り付けても、指示が無視されず応答が返る
5. 生成中にウィンドウのスクロールと中断操作が効く
6. アプリを再起動しても会話履歴が残っている
7. モデルの取得を途中で切断し、再開できる
8. 開発機で NFR-03 の速度を満たす

## 9. 未決事項

| # | 内容 | 決定が必要な時期 | 影響 |
|---|---|---|---|
| 1 | Apple Developer Program に加入するか | フェーズ4着手前 | 未加入なら配布不可。受入条件1を満たせない |
| 2 | Windows / Intel Mac に対応するか | フェーズ2着手前 | 対応するなら推論エンジンの選定と配布サイズが変わる |
| 3 | 配布対象は誰か（社内限定 / 一般公開） | フェーズ3まで | 公開範囲によりサポート・更新の設計が変わる |
| 4 | 同梱するモデルの利用規約（商用可否・再配布可否） | フェーズ3まで | モデルによっては再配布・商用利用に制限がある。**要確認** |
| 5 | RAG（FR-15）を初版に含めるか | フェーズ3着手前 | 含めるなら埋め込みモデルとベクトル検索の追加が必要 |

> #4 は配布を行う以上、法務上の確認が必要。「初回に利用者自身がダウンロードする」
> 形にすることで再配布に当たらない設計にできるため、本書ではその方式を前提とする（FR-07）。
