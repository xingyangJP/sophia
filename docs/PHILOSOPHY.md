## 0. この文書がある理由

**利用者（プロジェクトの発案者・所有者）の指示である。**

> **「二度と私の思想を忘れないようにしっかりドキュメントに書いて。README にも。細かい思想のドキュメントも。これは哲学と数学のプロジェクトだよ。」**（2026-08-23）

**「二度と忘れないように」と言われた背景がある。** 同じ日、設計の議論が2度、起点から外れた。

1. **ウェブ検索を「予算を食う機能追加」として却下しかけた。** 実際には**事実を外へ出してモデルを小さく保つ手段**であり、最終目標に向かう方向だった
2. **パーソナライズを「様式の調整」として扱っていた。** 実際には**この製品が成立する条件そのもの**だった

**どちらも文書に書いていなかったから起きた。** 書いてあったのは結論（1/1000・パーソナライズ）だけで、**なぜそれが答えなのかが無かった。** 結論だけが残ると、結論を守るために起点を裏切る判断が出る。

**本書は要約しない。利用者の言葉をそのまま引く。** 要約すると、次に読む人が元の思考を復元できない。

# 第一部 —— 哲学

## 1. 神を作ろうとしていない

> **「神を作ろうとしてるんじゃないよ。少ないエネルギーで会話が成り立つ。それはパーソナライズが鍵だという仮説が起点じゃなかったっけ？」**

**これがこのプロジェクトの起点である。**

いまのAIの進歩は「モデルの中に世界の事実をどれだけ詰め込めるか」の競争になっている。
詰め込むほど賢くなり、**エネルギーは青天井**になる。

**Sophia の仮説は逆を向いている。**

> **少ないエネルギーで会話が成り立つのは、モデルが世界を知っているからではなく、その人を知っているからである。**

この仮説が正しいなら、**モデルは小さくてよい。** 賢さで勝つのではなく、
**その人にとって不要なものを持たないことで勝つ。**

### 帰結: 置き場所が分かれる

| 何を | どこに置くか | 毎ターンの費用 |
|---|---|--:|
| **世界の事実**（変わる・膨大・その人と無関係） | **外に置く。要るときだけ取りに行く**（FR-30 ウェブ検索） | 取ったときだけ |
| **その人のこと**（変わらない・少量・その人そのもの） | **重みに焼く**（[DESIGN](DESIGN.md) 第14章 LoRA） | **0** |
| **言い方・行間** | その人専用の翻訳層（0.5〜1.5B） | 推論1回 |
| さっき話したこと | 会話履歴 | 既存 |

**検索はこの表の1行目である。** 事実をモデルの中に持つのをやめて外から取るのは、
**パラメータを減らす方向**であって増やす方向ではない。**1/1000 に向かう手段であり、それと戦うものではない。**

## 2. 一人でいい

> **「1億人に受け入れられるより、一人（パーソナライズ）でいいんだよ。」**

**これは規模の話ではない。費用の話である。**

汎用モデルは、**誰が読むか分からない**という前提で言葉を選ぶ。その前提が費用を生む:

- 安全側の但し書き
- 一般論の前置き
- 「専門家にご相談ください」
- 断定を避ける言い回し

**これらは全部、知らない相手に対する保険である。**
**相手が一人だと分かっていれば、その保険料は返せる。トークンでも、エネルギーでも。**

> **汎用モデルが払っている費用の大半は、知らない相手に対する保険料である。**
> **Sophia はその保険を買わない。買う必要がないから。**

**1億人に向けると、誰も怒らせない代わりに誰にも刺さらない言い方へ収束する。**
一人に向ければ、その収束から降りられる。

## 3. 嘘と逃げ —— 匙加減

> **「人は信じたい事を信じる生物。かといって嘘を言ったらダメ。その匙加減がバカと思われるか思われないかのバランスだと思う。」**

**「バカに見える」には2種類ある。片方だけを潰すと、もう片方に落ちる。**

| | 何をしたか | どう見えるか |
|---|---|---|
| **嘘** | 知らないことを、相手が聞きたい形で断言した | **一度バレたら全部信用できなくなる** |
| **逃げ** | 「一般には〜と言われていますが、状況によります」 | **正しいが、使えない。これも十分バカに見える** |

**汎用モデルが逃げるのは、1億人に対して安全な言い方を1つ選ばなければならないからである。**
**一人に向けてよいなら、その制約が消える。**

### 調整すべきものは「好み」ではない

**パーソナライズを「言い方の好み」の話だと読むと、この核心を外す。**

> **調整すべきは、どのくらいの確信で、どう言うか。その閾値そのものが人ごとに違う。**

同じ「たぶん動くと思います」を、ある人は「じゃあ動くんだな」と読み、
別の人は「わからないんだな」と読む。**モデル側の確信度が同じでも、受け取られ方が違う。**
だから調整すべきは中身ではなく**確信の表明の仕方**であり、
**それは一人に対してしか最適化できない。**

### 訂正には向きがある（FR-31）

**匙加減がずれたことは、訂正として現れる。ただし訂正は2方向ある。**

| 訂正 | 何がずれていたか | どちらへ動かすか |
|---|---|---|
| 「そんな断言できないだろ」 | **踏み込みすぎ** | 閾値を上げる |
| 「で、結局どっちなの」 | **逃げすぎ** | 閾値を下げる |

> **⚠ この2つは正反対なのに、向きを持たせずに記録すると、どちらも「訂正1件」として同じ形になる。**
> **焼き込めば打ち消し合って、何も学ばない。**
> **向きは、記録する時点で付けないと後から復元できない。**

**これが FR-31 の理由である。**

## 4. 禁じない

> **「禁じることをやめる。使い物にならない。」**

**掟は目的のために書かれる。目的から見て古くなった掟は、掟のほうが間違っている。**

2026-08-23、設計文書に残っていた3つの禁止が、実態より古くなっていた:

| 掟 | 目的だったもの | どうなったか |
|---|---|---|
| 会話も入力も外部へ出さない（NFR-01） | **秘密**。社内文書・顧客情報を外部APIに投げられないこと | **改定。** 出るものを「モデル取得」と「検索語」の2つに限って明示 |
| 4つ目のツールを足さない（16.4） | **速さ**。定義1つが `armed` の間ずっと毎ターンの費用になる | **既に解除済み**（`workspace_change` が4つ目として入っていた） |
| 読み取りだけに絞る（16.0） | **着手を止めないこと**。書き込みには承認フローと監査ログが要る | **既に解除済み**（`ToolApprovalBroker` / `ToolAuditStore` が実装された） |

**ただし目的は消えていない。** 禁止をやめても、**速さと秘密は測り続ける。**

> **禁止ではなく、可視化と計測に置き換える。**
> ツールを足すのは自由だが、**いくら払っているかは画面に出す。**
> 外へ出すのは自由だが、**何が出ていくかは送信前に見せる。**

**測らずに増やせば、Open WebUI の「こんにちは に34秒」へ自分で戻る。**

# 第二部 —— 数学

**哲学が「何を作るか」を決め、数学が「本当にそうなっているか」を決める。**
**このプロジェクトで最も多くの時間が溶けたのは、後者を怠ったときである。**

## 5. 費用は両側を数える

**2026-08-23 の最大の誤りは、監督役が検索の費用を片側しか数えなかったことである。**

数えたもの: 定義が毎ターン +約100 / 結果が +約183 / 利用者に残る枠は33しかない。
**数えなかったもの: 検索しない場合の費用。**

| | 検索する | 検索しない |
|---|---|---|
| トークン | 定義 +100、結果 +183（**栞にして落とせる**） | 訂正の往復3〜4回ぶんの発話 + **間違った答えが履歴に永久滞留（落とせない）** |
| 時間 | HTTP 1回 + 1往復 | **プリフィル21秒 × 3〜4往復** |
| 結果 | 答えが出る | **出ないまま重くなる** |

> **4bit 量子化の 8B は、知らないことを知っている顔で答える。**
> **利用者はそれを訂正する。往復のたびに会話は先頭から再プリフィルされる。**
> **そして間違った答えは会話の一部なので、栞にして落とせない。**

**測るべきは「1ターンの費用」ではなく「正しい答えに辿り着くまでの総費用」だった。**

> **⚠ これは [DESIGN 15.7](DESIGN.md) が扱ってきた形そのものである ── 器が対象を測っているか。**
> **予算配分表の数字は全部正しかった。表が問いに合っていなかった。**

## 6. 予算の算数 —— 33トークン問題

**`armed`（フォルダを結び付けた）会話の実測配分:**

| 項目 | トークン | 出所 |
|---|--:|---|
| 総額 | 1,000 | DESIGN 2.2章（連続使用時もプリフィル10秒以内） |
| 自己認識 + テンプレート固定分 | 105 | **実測** |
| ツール定義 | **499** | **実測** |
| 読み取り1回ぶんの置き場 | 183 | 割り付け |
| 栞 | 180 | 割り付け |
| **利用者に残る** | **33** | **配ったのではなく、余ったのがこれだけだった** |

**これは設計判断ではなく算数の結果である。** アプリ自身の都合で予算の97%が埋まっている。

> **⚠ この表は「守るべき制約」ではなく「症状」である。**
> **第14章（毎ターン注入をやめて重みへ移す）は、まさにこれを解くために書かれた。**
> **表を動かせない前提として扱うと、起点を裏切る判断が出る。実際に出た。**

## 7. 測る規則 —— R1〜R12

**同じ形の誤りが1セッションで4件出たとき、それは注意不足ではなく規則が無かったということである。**
規則の全文は [DESIGN 15.7・15.8](DESIGN.md) にある。ここでは骨だけ:

| # | 規則 |
|---|---|
| R1 | **本番の定義を import する。** テスト内に複製した計測値は無効 |
| R2 | **本番の会話ビルダーで組む。** system の有無・思考・`maxTokens` を出荷値に合わせる |
| R3 | **出荷されるシリアライズ経路を通す**（`tojson` の `\uXXXX` 展開で実測7倍の差が出た） |
| R4 | **陰性対照を置く。** 介入前から通る規則は何も測っていない |
| R5 | **陽性対照を置く。** 天井が存在することを確かめる |
| R6 | **表明は「落ちないこと」ではなく「正しい値か」に置く** |
| R7 | **合計が内訳と合わないときは、推測で埋めず実物を丸ごと出す。** 0件は答えではなく故障である |
| R8 | **器の検算を道具の中に組み込む** |
| R9 | **テストが実行されたことを数で確認する**（宣言と実行の突き合わせ。差はテスト名で列挙） |
| R10 | **既定で走らない計測が、値の正しさを守る唯一の仕掛けになってはならない** |
| R11 | **器を直したら、その器の誤差を引用している場所を全部探す。** 誤差は器に属する値である |
| R12 | **【確認済】の印を付けるなら、実物に紐づいた試験を伴うこと。** 印は読む人から確かめる動機を奪う |

### 数字についての2つの原則

> **① 数字は器と条件を連れて歩く。**
> 「494テスト・失敗0」は、未修理6件を失敗に数えないことで成立していた数字だった。
>
> **② 引用は検算ではない。**
> **数字は、引用されている限り検算されない。別の式に代入されたときに初めて検算される。**
> `measuredEstimateGap = 1.47` は、もう存在しない器（`content.count × 0.5`）の誤差だった。
> **補正済みの器に、補正前の誤差を掛けていた。** 誰かが別の式へ代入するまで、誰も気づかなかった。

## 8. 検索が数学の側で果たす役割

**「嘘をつくな」と「逃げるな」は、根拠が無ければ両立しない。**

根拠を持たないモデルに「嘘をつくな」とだけ言えば、**逃げるしかなくなる。**
逃げればバカに見え、訂正の往復が増え、**エネルギーを食う。**

> **検索は、断言してよい根拠を取りに行く仕組みである。**
> **だから結果は出典（URL）を伴わなければならない**(FR-30)。
> 出典があって初めて「〜によれば」という**第三の道**が成立する。
> **出典を落とすと、検索した意味の半分が消える。**

## 9. 一枚にすると

| 問い | 答え |
|---|---|
| 何を作るのか | **神ではない。** その人一人と、少ないエネルギーで会話が成り立つもの |
| なぜ小さくてよいのか | 事実は外から取れる。**中に持つべきはその人だけ** |
| なぜ一人でよいのか | **汎用の費用の大半は、知らない相手への保険料。**一人なら返せる |
| 何が難しいのか | **嘘をつかず、かつ逃げないこと。** その匙加減は一人にしか合わせられない |
| どう検証するのか | **訂正を向き付きで拾い、重みへ焼く。** 費用は毎ターン0にする |
| 何を測るのか | **1ターンの費用ではなく、正しい答えに辿り着くまでの総費用** |
| 何を禁じるのか | **禁じない。** 測って、見せる |
