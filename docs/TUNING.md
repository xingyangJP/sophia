# チューニングガイド（MacBook Air M3 / 16GB 前提）

このファイルは「性能を上げたくなったとき、どのつまみを回すか」の一覧。
上ほど効果が大きい。**1つ変えたら `make bench` で測る**。同時に複数変えると、
何が効いたのか分からなくなる。

---

## 0. まず前提：16GBの予算表

Apple Silicon はメモリをCPU/GPUで共有している。モデルに回せるのは全体ではない。

| 用途 | 消費 |
|---|--:|
| macOS 本体 + 常用アプリ（ブラウザ等） | 4〜6 GB |
| Ollama + Open WebUI | 約 1 GB |
| **モデルに回せる実質枠** | **約 9〜10 GB** |

モデルの必要量は「重み + KVキャッシュ」。KVキャッシュは `num_ctx` に比例して増える。

| モデル規模 | Q4_K_M の重み | +KV(8k) | 判定 |
|---|--:|--:|---|
| 4B | 約 2.6 GB | 約 3.0 GB | 余裕。下書き・分類など軽作業向き |
| 7〜8B | 約 4.7 GB | 約 5.4 GB | **常用の最適解** |
| 12B | 約 7.3 GB | 約 8.2 GB | 動くが、他アプリを絞る必要あり |
| 14B | 約 8.5 GB | 約 9.5 GB | ギリギリ。ブラウザを閉じる前提 |
| 27B以上 | 15 GB〜 | — | 不可。スワップして実用速度にならない |

枠を超えると macOS がスワップを始め、tok/s が数分の1まで落ちる。
「遅い」と感じたら、まず `ollama ps` と アクティビティモニタの
**スワップ使用領域** を見ること。ここが増えていたらモデルが大きすぎる。

---

## 1. モデル選択（効果：特大）

一番効くのはここ。量子化を1段落とすより、**用途に合ったモデルに替える方が効く**。

- 日本語の文章作成 → 日本語データを多く学習したモデル（Qwen3 系、Gemma 3 系）
- コード → コード特化モデル（Qwen2.5-Coder 系）。汎用8Bより明確に良い
- 分類・整形・要約のような単純作業 → 4B級で十分。速度が段違い

`docs/MODELS.md` に、試したモデルの評価を残していく。

## 2. 量子化レベル（効果：大）

同じモデルでも `Q4_K_M` / `Q5_K_M` / `Q8_0` でサイズと品質が変わる。

| 量子化 | サイズ比 | 品質 | 使いどころ |
|---|--:|---|---|
| Q4_K_M | 1.0 | 実用上ほぼ劣化を感じない | **既定。まずこれ** |
| Q5_K_M | 約1.2倍 | わずかに良い | メモリに余裕があるとき |
| Q8_0 | 約2倍 | ほぼ無劣化 | 16GBでは7B以下でのみ現実的 |

Q4 未満（Q3, Q2）は日本語の破綻が出やすいので、16GBなら手を出さなくてよい。

```bash
ollama pull qwen3:8b-q5_K_M   # 量子化を明示して取得
```

## 3. KVキャッシュ量子化（効果：大 / コスパ最良）

長いコンテキストを使うときのメモリを**ほぼ半減**できる。品質劣化は小さい。
`num_ctx` を伸ばしたいのにメモリが足りない、という場面の第一手。

```bash
launchctl setenv OLLAMA_FLASH_ATTENTION 1
launchctl setenv OLLAMA_KV_CACHE_TYPE q8_0
brew services restart ollama
```

`.env.example` に記載済み。`make env` で一括適用できる。
※ Flash Attention が有効でないと KV キャッシュ量子化は効かない。セットで入れること。

## 4. num_ctx（効果：大 / 諸刃）

コンテキスト長。**Ollama の既定は小さく、長い会話や長文貼り付けで
古い部分が静かに切り捨てられる**。「途中から指示を忘れる」の主因はほぼこれ。

一方で伸ばすほどメモリを食い、プロンプト処理も遅くなる。用途で決める。

| 用途 | 推奨 num_ctx |
|---|--:|
| 短い対話 | 4096 |
| 文章作成・要約 | 8192 |
| コード（ファイルを貼る） | 16384 |
| 長文書の読み込み | 32768（12B以上との併用は不可） |

Modelfile に焼き込むのが確実（`modelfiles/*.Modelfile` 参照）。

## 5. モデル常駐の制御（効果：中）

- `OLLAMA_KEEP_ALIVE`（既定5分）— 使うたびに再ロードされるなら伸ばす。
  ただし常駐中はメモリを占有し続ける。`30m` あたりが折衷点
- `OLLAMA_MAX_LOADED_MODELS=1` — **16GBでは必ず1**。
  既定のままだとチャット用とコード用が同時に載り、両方遅くなる
- `OLLAMA_NUM_PARALLEL=1` — 同時実行数。1人で使うなら1が最速

## 6. 生成パラメータ（効果：品質側）

速度ではなく**出力の質**に効く。Modelfile で用途ごとに固定する。

| パラメータ | 文章作成 | コード | 意味 |
|---|--:|--:|---|
| `temperature` | 0.7 | 0.2 | 高いほど多様、低いほど堅実。コードは低く |
| `top_p` | 0.9 | 0.9 | 候補の絞り込み |
| `repeat_penalty` | 1.1 | 1.05 | 同じ表現の繰り返しを抑える |

「同じことを何度も書く」なら `repeat_penalty` を上げる。
「無難すぎる/つまらない」なら `temperature` を上げる。

## 7. システムプロンプト（効果：中 / 手間ゼロ）

**最も費用対効果が高い改善**。モデルを替える前にここを詰める。
役割・読者・文体・禁止事項を書くだけで、出力の当たり外れが目に見えて減る。
`modelfiles/` で管理し、育てたら `make models` で焼き直す。

## 8. MLXバックエンド（効果：中 / Apple Silicon限定）

導入した Ollama は `mlx-c` に依存しており、Apple 純正の MLX を通せる構成。
対応モデルでは Metal 経由より速くなることがある。
ただし全モデルが対応するわけではないので、**必ず `make bench` で前後比較**すること。
速くならないケースもあり、その場合は戻す。

## 9. 熱（効果：特大 / Air特有・**実測で確認済み**）

MacBook Air はファンレス。**連続使用で tok/s が約半分に落ちる**（実測）。

| 実行順 | sophia-coder | sophia-chat |
|---|--:|--:|
| chat先行 | 9.0（2番目） | 13.4（1番目） |
| coder先行 | **14.1（1番目）** | **7.0（2番目）** |

先に走った方が速い。**これはどのつまみを回しても覆せない、最大の変動要因**。
ベンチが前回より遅いときは、設定を疑う前にまず本体の熱を疑うこと。

- **比較計測は必ず冷えた状態に揃える。** 揃えないと計測に意味がない
- 長時間の連続生成は避け、間隔を空ける
- 底面を塞がない（膝上・布の上を避ける）
- 連続使用時の実力値は **7〜9 tok/s**。冷間の13〜14 tok/s は瞬間値でしかない

## 10. 思考モード（効果：特大 / 対応モデルのみ）

`qwen3` 系は応答前に思考テキストを出力する。**体感速度への影響が最も大きいつまみ。**

| 条件 | 思考 | 本文 | 消費トークン | 本文が出るまで |
|---|--:|--:|--:|--:|
| 有効（既定） | 1,075文字 | 112文字 | 300（上限到達） | **15〜29秒** |
| 無効 | 0文字 | 56文字 | 32 | **0.2秒** |

**トークン予算の9割が思考に消える。** 生成上限が小さいと本文に到達せず打ち切られる。

```bash
# 思考を止める（短い質問はこちらが圧倒的に速い）
curl http://localhost:11434/api/generate \
  -d '{"model":"sophia-chat","prompt":"...","think":false}'
```

使い分け:

| 用途 | 思考 | 理由 |
|---|---|---|
| 短い質問・定型作業・翻訳 | **無効** | 待ち時間が消える。品質差はほぼ出ない |
| 複雑な推論・設計相談・デバッグ | **有効** | 思考が効く領域。ただし `num_predict` を1024以上にすること |

**思考モードを有効にしたまま `num_predict` が小さいのが最悪の組み合わせ。**
待たされた末に答えが返ってこない。

## 測り方の作法

```bash
make bench                      # 現状をざっと見る
# つまみを1つ変える
make bench-save NOTE="KV量子化 q8_0 を有効化"   # 履歴に残す
```

`docs/BENCH_RESULTS.md` に条件付きで蓄積される。
体感に頼ると熱や気分で判断がぶれるので、**数字で比較する**こと。

### 設定変更の前後を比較するときは冷却を入れる

第9章のとおり、冷却なしで複数モデルを続けて測ると**後のモデルが最大2倍遅く出る**。
つまみの効果を見たいのに、熱の差を測ってしまう。

```bash
python3 scripts/bench.py --models sophia-chat --cooldown 120 --save --note "変更前"
# つまみを変える → make restart
python3 scripts/bench.py --models sophia-chat --cooldown 120 --save --note "変更後"
```

さらに厳密に測りたいときは:

- 他のアプリ（ブラウザ・Open WebUI・エディタ）を落とす
- 電源に接続した状態で揃える（バッテリー駆動では省電力制御が入る）
- 同じ順序・同じ時間帯で測る

**絶対値より差分を見ること。** 環境を完全に揃えるのは現実的でないため、
同じ条件で前後を比べる方が判断を誤らない。
