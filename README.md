## このプロジェクトは何か

生成AIを業務で使うとき、入力内容が外部サービスへ送られることが制約になる。
社内文書・顧客情報・未公開のソースコードは、外部APIに投げる判断がしにくい。

Sophia はその制約を外すために、**モデルの実行から配布まですべてローカルで完結する
デスクトップアプリ**を macOS ネイティブ（SwiftUI + MLX）で作る。
さらに、既存モデルを使うだけでなく、**自分のデータで鍛えた独自モデル**を
その中で動かすことを目指す。

そしてその先に、本当の目標がある。

> **新しいアプローチによって、現在の約1/1000のエネルギーで同じ仕事をするAIを作る。**
> アプリも独自モデルも、そこへ至る通過点である。 — [docs/VISION.md](docs/VISION.md)

### 2つの目的

| | 内容 |
|---|---|
| **A. アプリ（器）** | Claudeデスクトップアプリのような使用感を、ローカルモデルで実現する。**他人にも配布できる単体アプリ**として仕上げる |
| **B. モデル（中身）** | 新しい重みを持つモデルそのものを開発する。ローカルで着手し、性能を上げ、上限に達したらクラウドへ移行する |

両者は独立して進む。接点は**モデルファイル1個**だけで、
どちらかの完成をもう一方が待たない構造にしてある。

> RAG（外部文書に検索をかける手法）は目的Bの代替にならないため、対象外としている。
> 目的はモデルの振る舞いを外側から変えることではなく、**モデル自体を作ること**にある。

## 使い方

### アプリ（フェーズA1）

```bash
make app-setup   # 初回のみ: Metal ツールチェーン導入（約688MB）
make app-run     # ビルドして起動（Debug）
make app-test    # 永続化層の単体テスト（GPU・モデル不使用）
```

初回起動時にモデル（Qwen3-8B 4bit / 約5GB）の取得が必要。

### 開発用バックエンド（Ollama + Open WebUI）

```bash
make up        # Ollama と Open WebUI を起動
make status    # 稼働状況といまメモリに載っているモデル
make down      # 停止
```

起動後 `http://localhost:8081` をブラウザで開く。
**アプリ（MLX）と Ollama は同じメモリを取り合うため、16GB機では同時に使わないこと。**

性能を変えたいときは [docs/TUNING.md](docs/TUNING.md) でつまみを1つ選び、
`.env` か `modelfiles/*.Modelfile` を編集して `make restart` または `make models`。
効果は `make bench-save NOTE="変えた内容"` で数字として残す。

> **Modelfile は編集しただけでは反映されない。`make models` が必要。**

## 前提と制約

- **開発機**: MacBook Air M3 / 16GB / ファンレス
- モデルに回せる実質枠は **約9〜10GB**。7〜8Bが常用の最適解、14Bが上限
- 長時間の連続生成では熱制限で性能が落ちる
- Open WebUI は **8081** で待ち受ける（既定の8080は開発機上の別プロジェクトと衝突するため）。
  `.env` の `WEBUI_PORT` で変更できる

制約の詳細と対処は [docs/TUNING.md](docs/TUNING.md) 第0章。
